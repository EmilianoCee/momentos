# momentos

A place to build intuition for maths, physics, signals, systems and circuits, and to find out, with evidence,
how well you actually understand them.

It has three parts.

- **A knowledge map** ([`index.html`](index.html)): every idea is a piece of text, every folder a circle, and
  every hairline a connection that says what carries over from one idea to the next.
- **Small interactive tools:** drag a vector, sweep a frequency, watch a capacitor charge. Each one exists to make
  a single idea click.
- **A mastery record:** quizzes that find your level on each topic, grade your answers against written anchors,
  and bring topics back for review before you forget them.

The map, the tools, the plans and the quizzes are shared. Your levels and your history are yours: they live in a
folder that git ignores, so a fork never carries anyone else's record.

Most of this is built with an LLM and then checked. See [Accuracy](#accuracy).

## Start here

Open [`index.html`](index.html) in a browser. Click a topic to see what it builds on, what it leads to, a question
to check yourself with, and its tool if it has one. Scroll to zoom, drag to pan, press `/` to search. Upright text
has a tool behind it. *Italic* text is planned.

## Start your own record

One step, from the root of your fork (it needs Python 3, nothing else):

```bash
python3 scripts/learner.py init your-handle
```

That creates `learner/`, which is ignored by git and is its own private git repository. Pick a handle, not your
name. Then open `learner/profile.md`, list your courses, and ask an LLM that can read the repo for the onboarding
quiz ("onboard me"). [docs/learner-record.md](docs/learner-record.md) explains every file.

Pulling updates from the original repo can never touch `learner/`.

## Get quizzed

In Claude Code, or any agent that reads `AGENTS.md`, say one of these from the repo root:

| Say | What happens |
|---|---|
| `quiz me EE 120` | questions on that course, weakest and most overdue topics first, mixed across topics |
| `quiz me convolution` | one topic, pitched one level above where your evidence puts you |
| `review` | whatever is due today |
| `exam prep EE 105 FINAL` | questions weighted by how often each topic has been examined |
| `where am I` | your progress in each course against its mastery target |

The session reads your record, asks one question at a time, grades each answer, and writes the evidence back.

With no repo access (a chat in a browser), run this and paste what it prints:

```bash
python3 scripts/learner.py export --course "EE 120"
```

The chat ends with an evidence block. Paste it back with `python3 scripts/learner.py paste`.

### The ladder

Understanding belongs to a topic, not to a person, so a level is kept per topic.

| Level | You can |
|---|---|
| L0 unseen | only recognise the name |
| L1 recognise | state the definition with notes open |
| L2 compute | solve the standard problems by procedure |
| L3 picture | explain why, sketch it, predict what a parameter change does |
| L4 use | solve an unfamiliar problem with it, and say where it breaks |
| L5 teach | derive it from scratch and connect it to other fields |

Mastery is L4, with evidence, still holding at a review a week or more later. A self-rating never counts for more
than L1. The rules are in [docs/levels.md](docs/levels.md), and why they are what they are is in
[docs/mastery.md](docs/mastery.md).

## Add a tool

1. Start from confusion: something you can compute but cannot picture.
2. Ask for the next one on the list ("build the next tool"), or write a plan for your own idea ("write a plan for
   ..."). Plans are in [`plans/`](plans/BACKLOG.md), and their format is in [docs/plans.md](docs/plans.md).
3. The tool is one self-contained `.html` file in its topic's folder. The rules are in
   [docs/tools.md](docs/tools.md).
4. Before committing: `python3 scripts/build.py`, then `python3 scripts/check.py`.

## What is inside

```
index.html         the knowledge map (its data is generated from map/)
map/               the map's source, one small file per folder
maths/ physics/ signals/ systems/ circuits/ devices/    the tools, by area
curricula/         what each course covers, where it is assessed, and the mastery target
rubrics/           what each level looks like on each topic, for grading
plans/             one plan per tool, and the backlog in priority order
prompts/           the learning pre-prompt and the quiz protocol for a plain chat
templates/         the starting point for a tool and for a learner's record
scripts/           build, check, the learner record, the maths tests
docs/              the charter, the conventions, the decision records
AGENTS.md          the rules every LLM follows in this repo (CLAUDE.md imports it)
learner/           yours alone, never shared (created by the command above)
```

To add a course of your own, paste [prompts/add-my-courses.md](prompts/add-my-courses.md) into an agent. The work left on the shared content is in [docs/roadmap.md](docs/roadmap.md).

## Accuracy

A tool built by an LLM can look convincing and be subtly wrong: a sign error, a mislabelled axis, an approximation
that holds only in a special case. Three things guard against that here.

- Every tool keeps its maths apart from its drawing, with check cases beside it, and
  `node scripts/test-tools.js` runs them.
- A tool built from a plan carries the plan's check cases, which were computed by a separate reference script.
- The header of each tool has a `Checked:` line saying what was compared with what. It is only written for
  something that was actually checked.

That is not the same as checking a tool against your own lecture notes, which is still worth doing the first time
you use one. If something turns out wrong, fix it or delete it. A wrong intuition is worse than none.
